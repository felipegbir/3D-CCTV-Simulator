# N.O.M.A.D. 8e.7.3 — Camera identity, optical geometry, and report viewpoints

## Release purpose

8e.7.3 prepares the accepted 8e.7.2 baseline for engineering review by correcting saved camera identity, replacing stale vertical-FOV assumptions with sensor-aware geometry, and preventing report overview/context captures from being generated beneath the grid or model.

## Implemented

- `createCameraObject()` accepts an immutable explicit ID when restoring saved cameras.
- Project loading restores by saved ID, restores renamed display names, advances the automatic counter beyond restored numeric IDs, rejects runtime collisions, and repairs missing/duplicate legacy IDs with a visible warning.
- One authoritative VFOV helper derives vertical field of view from HFOV and the actual resolution aspect ratio.
- The Three.js render camera uses calculated VFOV and actual sensor aspect; footprint height, vertical pixel density, presets, and ROI metrics use the same geometry.
- Saved preset and ROI analyses are recalculated during project restoration so stale stored values cannot survive the optics correction.
- Report scene and camera-context viewpoints are scene-bounded, clamped above the grid/floor, and rotated horizontally for the opposite view without mirroring elevation below the model.
- Preset report cameras use the source sensor aspect ratio and retain ROI overlay composition.

## Compatibility

- Project schema remains version 7 because no storage structure was removed or made incompatible.
- Existing `.nmd` projects remain readable. A corrected save preserves restored or repaired IDs and refreshed derived values.
- The verified 8e.7.2 tag and repository backup remain the rollback baseline.

## Deferred productization comparison

Docker Compose, PostgreSQL camera-catalog migration, CSV database maintenance, and React UI integration remain pending receipt of the Hitachi Engineering repository. They must be compared on a separate integration branch before any UI or persistence cutover.

## Required owner QA

1. Load a project containing renamed/deleted/sparse camera IDs; save and reopen it.
2. Verify each camera retains its model, PTZ presets, depth target, and ROIs.
3. Compare 16:9 and 4:3 camera footprints and vertical pixel density.
4. Generate a report and verify both scene views and every camera-context image are above the grid and useful.
5. Verify preset images retain the sensor framing and ROI overlays.
